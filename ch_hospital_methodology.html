CH-IQI 2023 Dashboard

Methodology & Data Notes

This page explains how the CH-IQI hospital interventions dashboard is assembled — from sourcing the raw spreadsheets to modelling the taxonomy, calculating volumes, and designing the interactive experience.

Last updated: February 2025 Contact: a.j.im@umail.leidenuniv.nl

How to use these notes

The dashboard is intended for journalists, patients, and policymakers who want a quick overview of where specific interventions are performed in Switzerland. The sections below document the decisions that shape the dataset and the interface so that the results can be interpreted appropriately and — if needed — replicated.

1. Data sources & coverage

All figures come from the Swiss Federal Office of Public Health (FOPH) CH-IQI release covering the 2023 reporting year. The raw Excel workbooks list the number of in-patient stays and risk-adjusted indicators for acute-care hospitals.

Files consulted

  • Hospital-level case volumes by procedure group ("Fallzahlen je Spital und Indikator").
  • Metadata tables describing CH-IQI indicators, risk adjustment, and national inclusion criteria.
  • Reference sheets mapping cantons, hospital identifiers, and organisational types.

Temporal & geographic scope

  • Observation window: discharges between 1 January and 31 December 2023.
  • Hospitals: all acute-care institutions participating in the CH-IQI programme.
  • Geographies: cantonal assignment based on the legal headquarters of each hospital site.

Suppressed values (< 5 cases) remain hidden in the source material. The dashboard keeps these suppressions in place to protect patient privacy.

2. Cleaning & harmonisation

The raw workbooks were exported from the FOPH portal as XLSX files and processed in Python (Pandas 2.2). The goal was to deliver a tidy table where each row represents one hospital–procedure combination.

Processing steps

  1. Normalised column headers to consistent English labels while preserving the original German titles as metadata.
  2. Reshaped the wide sheets into long format so each procedure appears as an explicit row.
  3. Trimmed hospital names, aligned legal entities across sheets, and attached canton codes and ownership type.
  4. Converted suppressed cells to null values and flagged them for the interface.
  5. Stored the cleaned table as a UTF-8 CSV that powers the client-side search catalogue.

Quality checks

  • Spot-checked aggregate volumes against national totals published by FOPH.
  • Validated canton assignments against the BAG list of hospital sites.
  • Ensured each hospital–procedure pair is unique and carries at most one data row.

3. Procedure taxonomy

CH-IQI indicators are grouped into thematic clusters (e.g., cardiology, orthopaedics). For usability, the dashboard exposes a curated set of "quick picks" and a browsable catalogue.

  • Indicator names and codes follow the official CH-IQI nomenclature.
  • Specialty groupings are maintained from the source metadata to avoid introducing ad-hoc categories.
  • Additional synonyms were authored for the search index (e.g., "hip replacement" alongside the German descriptor).

When the user selects an indicator, the dashboard loads all hospitals with available volume data and displays supporting metadata such as the case mix and applicable quality indicator.

4. Metrics & calculations

The dashboard presents annual case volumes and, where available, the CH-IQI quality indicator for the selected procedure. No additional statistical modelling is performed in the browser.

Displayed fields

  • Total number of cases reported in 2023.
  • Hospital type (university, central, regional, specialised).
  • Canton of the hospital site.
  • Suppression flag indicating if the underlying count is hidden.

Derived indicators

  • Sorting logic ranks hospitals by case volume and falls back to alphabetical order for ties.
  • Dashboard totals aggregate the visible (non-suppressed) rows for contextual messaging.

Risk-adjusted outcome measures (e.g., mortality, readmission) remain in their native format. They are surfaced alongside the volume data without further manipulation.

5. Dashboard interactions

All interactions run client-side in vanilla JavaScript using the cleaned CSV and a GeoJSON file of Swiss cantons.

  • Search & quick picks: fuzzy matching on indicator names, codes, and synonyms.
  • Filtering: hospital type and canton filters reduce the in-memory dataset before rendering.
  • Map: Leaflet 1.9 renders canton boundaries; hospitals inherit the canton colour scale for consistency.
  • State management: selections persist in localStorage so the user keeps context when switching languages.

The dashboard intentionally avoids remote calls so it can be hosted as a static page on GitHub Pages while remaining responsive.

6. Caveats & known limitations

  • Suppressed values (< 5 cases) can understate activity for rare procedures.
  • Quality indicators are not directly comparable across specialties because of differing risk adjustments.
  • Hospitals with multiple locations appear under their legal entity; site-level nuances may require consulting the FOPH release.
  • Only acute-care hospitals are covered; rehabilitation and psychiatric facilities are outside the CH-IQI scope.

7. Reproducibility checklist

To reproduce or extend the dashboard, follow the steps below. The source notebooks (Python 3.11) live alongside the cleaned data in a private workspace but can be shared on request.

  1. Download the CH-IQI XLSX bundle for the desired year from the FOPH website.
  2. Run the data preparation notebook to clean and export the consolidated CSV.
  3. Refresh the procedure metadata JSON that feeds the catalogue and search synonyms.
  4. Regenerate the static assets (minified JavaScript, GeoJSON simplification if boundaries change).
  5. Deploy the site via GitHub Pages or another static host.
